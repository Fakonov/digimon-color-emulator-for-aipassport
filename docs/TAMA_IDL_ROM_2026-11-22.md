# fw_tg13_jp_v48 iD Lovely Melody ROM 分析：对本项目提速是否有帮助

结论：**没有帮助，零收益。** 下面是判定依据。

## 1. 这是什么文件

| 项 | 值 |
|---|---|
| 路径 | `C:\Users\DuWeisi\Desktop\dsh sth\tama dg roms\tama整合\固件\tama_id_idl\fw_tg13_jp_v48_2010_09_17_iD_Lovely_Melody.bin` |
| 大小 | 4,194,304 B（4.00 MiB） |
| SHA-1 | `bf37c5df6f62003e7b4c20f9fb7dd021baa94a77` |
| 非零字节 | 3,434,774（0xFF 占 1,395,876，另有 759,530 个 0x00） |
| 头 4 字节 | `EA 39 C9 00` → 小端 0x00C939EA，即复位向量 |
| 向量表 | 前 512 B 共 128 项，只有 33 个不同目标，全部落在 `0x00C93xxx–0x00C99xxx`；最高频目标 `0x00C99076` 出现 88 次（中断空桩） |
| 大段空白 | 6 段 ≥8 KiB 的 0xFF，最大 `0x2ED380–0x3D27FF`（939,136 B） |

架构判定：**Epson S1C33 系列**（32 位 RISC，片内 ROM 映射在 0x00C00000）。判定依据是向量表全部指向 0x00C9xxxx 段、代码区出现大量 `xx C0` 形式的 16 位指令字（S1C33 的 16 位基本指令 + EXT 扩展字）。

## 2. 为什么它帮不上忙

本项目模拟的是 **GeneralPlus GPCE4 + unSP**（16 位 CISC，48/96 MHz，内部 mask ROM + SPI flash 双地址空间）。S1C33 与 unSP 之间：

- 指令集不同（32 位 RISC vs 16 位 CISC）
- 内存映射不同（0x00C00000 片内 ROM vs 0x004000 内部 ROM + 0x200000 flash 直窗）
- 外设模型不同（S1C33 的 I/O 与 GPCE4 的 `0x3000–0x30EF` 无任何交集）

**没有一行代码、一个数据表可以迁移。** 即使把这份 ROM 完整反汇编，得到的也只是拓麻歌子的游戏逻辑，与数码暴龙机的运行速度无关。

## 3. 它其实已经跑在同一颗 C3 上了

FoloToy 的 `plays/2247` 项目固件 `tmp/tama-id-melody.bin`（7,011,600 B，SHA-1 `8ba1a05039195b43218186a4d54660bad6a67f9c`）在文件偏移 **0x466AD2** 处与本 ROM 的前 12,288 字节**逐字节相同**，之后转入 `MLROM48` 分块压缩容器。也就是说：

- 同一份 ROM，同一颗 ESP32-C3，那个项目跑得动；
- 所以「研究这份 ROM 能不能让 C3 快起来」，答案在**固件**里，不在 ROM 里；
- 而那份固件已经静态分析过（见 `tmp/research_plays_2247.md`）：它是**纯解释器**，没有绘制 HLE，没有 JIT。

## 4. 唯一有价值的对比：单价差 10 倍

| | Tama-iD（S1C33） | 本项目（GPCE4/unSP） |
|---|---|---|
| guest 时钟 | 18.432 MHz | 96 MHz |
| 宿主时钟 | 160 MHz | 160 MHz |
| 每 guest 周期可用宿主周期 | 8.68 | 1.67 |
| 实现方式 | 解释器（逐条 switch） | AOT（每条展开约 11 条 RISC-V） |
| 约合宿主周期/guest 指令 | **≈10** | **110（实测）** |

他们能流畅，不是因为 ROM 里有加速技巧，而是因为 **S1C33 翻成 RISC-V 接近 1:1**，而 unSP 的每条指令要摊上 11 条 RISC-V 加一次 AotCtx 访问。这是生成器架构问题，不是 ROM 问题。

## 5. 本次分析额外确认的三件事

1. 该 ROM 无加密、无压缩，可直接反汇编（若有人要做 S1C33 模拟器）。
2. 6 段大块 0xFF 说明固件里有 1.36 MB 未使用空间——这解释了为什么官方能在同一颗芯片上出多个版本（iD / iD L / Princess Spacey）。
3. 字节 `0x11` 出现 334,452 次，是图形/字模数据的典型填充值，说明资源以位平面或索引色存储，不是逐像素 RGB565。

## 6. 对你的问题的直接回答

想靠分析这份 ROM 让数码暴龙机跑快，**做不到**。本项目重绘帧的瓶颈是 154,451 条 guest 指令 × 110 主机周期，已经量化到顶（`docs/PERF_2026-11-22.md`）。ROM 侧能砍的上限是 1.5×（重绘帧只推约 1,300 像素，不是整屏），而换 ESP32-S3 是 1.8–2.2×。

如果目标是「让这台机器也能玩拓麻歌子」，那是另一个项目：需要 S1C33 模拟器，而 FoloToy 已经做完了。
