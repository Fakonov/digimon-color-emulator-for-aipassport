## 1. UI 差异（agent `580e7bc9`）

### 1.1 参考板的技术栈

不是裸像素绘制，是 **LVGL 9 控件树** + 默认主题 + **Montserrat 14**：

| 事实 | 出处 |
|---|---|
| 默认字体 Montserrat 14 | `lv_conf_internal.h:2054`、`sdkconfig:2238 CONFIG_LV_FONT_DEFAULT_MONTSERRAT_14=y` |
| `.line_height = 16`、`.base_line = 3`、大写墨高 **10 px** | 字体表 |
| 比例字，`adv_w` 单位 1/16 px：空格 3.75、`S` 8.69、`W` 15.75 | 字体表 |
| 菜单源码里**没有** RGB565 字面量，全是 24 位 RGB888 交给 `lv_color_hex()` | `digimon_app.c:2694-2766` |
| 字体**不从游戏 ROM 提取** | 全文件确认 |
| `lv_anim` **0 命中**，菜单没有开合动画，只有 `LV_OBJ_FLAG_HIDDEN` 切换 | 全文件 grep |

源码里两处**注释与代码矛盾**，按代码记录：

- `2202` 处把选中行文字色设成 `MENU_INK`，但 `2471-2473` 的注释自己承认行级文字色对标签无效 → 实际选中行文字仍是 `0x252C1F`。
- 版本号注释写 bottom-right，代码是 `LV_ALIGN_TOP_RIGHT`（`2756`）。

### 1.4 已落地 / 未落地

**已落地**（`firmware/digicore-c3/main/menu.cpp`）：`kPanelEdge 0x2984`、`kInk 0x2163`、

## 2. 按键长按（agent `d1ef439c`）

### 2.1 参考板的机制：不吞键，到点主动释放

这一点和直觉相反，值得单独记：

> 按下照常转发给 ROM → 到点主动释放并标记 → 吞掉自己产生的那次松开

`digimon_app.c` 证据链：`:3695` `rom_key(e.mask,1)` 转发按下、`:3732` 到点 `rom_key(1,0)`
主动释放、`:3731` 设 `s_ok_held_consumed=true`、`:3621` 随后的松开被 `continue` 丢弃。
注释 `:3726-3727` 原文：

> The ROM had the C press forwarded already, so let it go now

全程**没有任何一处"按下就拦下来"**。参考板接受"长按会让游戏里多一次按键"这个副作用，
处理办法是尽早结束那次按下。

### 2.2 阈值有实测依据

| 常量 | 值 | 位置 | 依据 |
|---|---|---|---|
| `MENU_HOLD_US` | **1500000** | `:337` | `PROGRESS.md:5047-5052` 记录 3.0 → 1.8 → 1.5 的调参过程；`:5219` 说再短就该换手势 |
| A+C 长按 | **1200000** | `:356` | `:3762-3768` 的实测注释；同族 ROM 700 ms 不认、3200 ms 才认（`PROGRESS.md:3841-3862`） |
| `KEY_MIN_HOLD_US` | 50000 | `:371` | 最短保持，避免 ROM 抖动丢键 |
| `ROM_HOLD_US` | 1500000 | `:178` | **死常量**，全文件只命中定义处，没人用 |

原机**没有长按语义**（`README.md:41`：长按只会被按键扫描当成反复按下）。

### 2.3 规则表（R1–R18 摘要）

| # | 手势 | 界面 | 动作 |
|---|---|---|---|
| R1 | 短按 A | 主屏 | 转发按下 + 松开；<50 ms 的松开被推迟到 50 ms |
| R2 | 长按 A ≥1.2 s | 仅 `mode==1 && sub==0`，菜单关、屏未熄 | 放掉 A → 持续按住 A+C，到 RAM(0x00A) 变化或 3.2 s |
| R3 | 长按 A ≥1.2 s | 其它界面 | 无特殊动作（"Elsewhere A stays a plain key."） |
| R4 | 短按 B | 主屏 | 进图标功能页 / 切时钟页 |
| R5–R8 | 短按 B | 各二级页 | 执行当前行 |
| R9 | 长按 B ≥2 s | 卡片选择器 | 进"清清单卡战绩"确认，10 s 过期 |
| R10 | 短按 C | 游戏内 | 取消 / 返回 |
| R11 | 长按 C ≥1.5 s | 游戏内、菜单关 | **按住期间**主动释放 C + 开菜单 |
| R12 | 长按 C 后松开 | 菜单已开 | 被 `consumed` 吞掉 |
| R13 | 短按 C | 菜单已开 | 按下不进 ROM，松开 → 关菜单 |
| R16 | 菜单内任意键 | 菜单已开 | 没有一个键进 ROM |
| R17 | 任意键 | 屏已熄 | 只唤醒，按下+松开**两个边沿都吞** |

**注意 R18 的掩码与我们的相反**：参考板 `4=A 2=B 1=C`，我们是 `1=A 2=B 4=C`。

## 3. 设置项生效链路（agent `8eb8b934`）

### 3.1 链路表

| 设置项 | NVS 键 | 默认 | 消费点 | 真生效? |
|---|---|---|---|---|
| AUTO OFF | `digicore/auto` | 16 s | `app_main.cpp` 熄屏判断 → `display_backlight_set(0)` | 是 |
| BRIGHT | `digicore/bright` | 80% | 熄屏模块 + `display.c` `duty = 1023*pct/100`（LEDC） | 是（`13d400d` 修了"只在亮灭翻转时才写"的 bug） |
| VOLUME | `digicore/vol` | **20%** | `audio_set_volume()` → `audio.c` 寄存器 + `render_beep()` 的 16 bit 幅度 | **只一半** |
| AUTO SAVE | `digicore/save` | 60 s | `maybe_snapshot_machine_state()` 周期 | 是 |
| VERSION | 无 | 编译期 `DIGICORE_VERSION` | 仅渲染 | 是 |

### 3.2 VOLUME 的硬伤（设计，不是 bug）

`audio.c` 的 `audio_set_volume()` 无论 pct 多少都写 `reg_w(0x32, 0xBF)`，即把 codec
钉在 **0 dB**，音量只走 `render_beep()` 的 16 bit 数字幅度。

原因是实机验证过：ES8311 的 REG32 在 `0xBF` 时出声最干净（`0x00` 是 −95.5 dB、
`0xFF` 是 +32 dB），改它会引入失真。**0% 是数字静音，不是硬件 mute。**

### 3.3 AUTO SAVE 的寿命

最坏情况（宠物持续动 + 60 s 档）：每年约 65,700 次/扇区，NOR 100k 次 ≈ **1.5 年**。
`snapshot_machine_state()` 里的 RAM CRC 去重能把静止期降到接近零，实际远高于这个数。

### 3.4 已修的开机顺序问题

| 问题 | 修法 |
|---|---|
| 背光先按编译期默认值亮，再跳到存着的亮度 | `menu_load()` 挪到 `display_init()` 之前 |
| 开机提示音永远用 `audio.c` 里写死的 55% | `audio_init()` 之后、开机提示音**之前**补 `audio_set_volume(menu_volume_pct())` |
| 菜单打开时 `blit_frame()` 的 idle guard 会强制重推 256×224，把卡片打穿 | `blit_frame()` 改为 `if (s_display_ok && !menu_is_open())` |
| AUTO OFF 设成 NEVER 时 banner 不出现 | banner 条件改成 `(auto_off == 0) || (auto_off > kMachineIdleSec)` |

### 3.5 未做

- **FOLLOW 16S 没有真的跟随 guest**：它只是模拟器自己的 16 s 定时器，没有读 guest 是否黑屏。
  要做需要读 guest RAM 或监听背光寄存器。
- **AUTO OFF 的 NEVER / 0% 音量没有显式早退**，靠条件短路。

## 4. 下一轮可以直接接着做的三件事

按价值排序，都写清了入口：

1. **比例字渲染器**（`menu.cpp` 的 `draw_char`/`text_width`）
   参考板 Montserrat 14，大写墨高 10 px、行盒 16 px。做法：给 5×7 字模配一张字距表，
   `adv[i]` 按字形宽度取 4/5/6（现在统一 6×2=12），`text_width` 改成累加。
   这一步能把"文字宽度差 20–38%"消掉，是"看起来一样"的最大单项。

2. **alpha 混合**（卡片 90% 底 + 12 px 40% 阴影）
   现在 `card_line()` 是直接赋 RGB565。要混合得先取背景（`backdrop_px()` 已经有了），
   再按 90/100 和 40/100 算。注意这是每像素乘加，320×240 全屏 = 76,800 次，
   在 160 MHz C3 上要测一下能不能塞进一帧。

3. **A+C 的界面门**（D2）
   需要先给 `Gpce4` 加 `uint16_t ram_at(uint32_t addr)`，再用 `Q` 命令或新命令扫出
   彩色 ROM 的 mode/sub 地址。地址没确认前不要填 —— 填错比不填更糟。
