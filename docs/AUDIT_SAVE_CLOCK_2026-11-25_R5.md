# 第五轮：时钟编辑不能生效（v1.11.1）

日期：2026-11-25
基线：v1.11.0
版本：**v1.11.1**（已烧 COM4，只写 app 分区）

## 0. 现象

用户在时钟界面发 A+C 打开 ROM 自己的时间编辑，改完按 C 确认，界面上的时间又回到 A+C 之前。
关机重开后：CONTINUE → 调整时间界面 → 无论怎么调，按 C 后进入的是正确的最后存档状态（存档没坏，只是时间改不动）。

## 1. 根因

v1.10.1 为了修"读档把旧时钟当玩家操作"的污染，把"采纳玩家时间"整条删了，锚点变成唯一真相。
于是 `clock_sync()` 每 250 ms 检查一次，发现客人时钟与锚点差 > 1 s 就写回 —— 玩家刚提交的时间在 250 ms 内被覆盖，看起来就是"按 C 又跳回去"。

## 2. 修法：用硬件写操作识别"玩家提交"

不再靠 RAM 跳变猜。ROM 的提交函数（flash `0x204179`）是唯一一个**在 `0x0CB0` 已置 1 之后**
写 `Timebase_Clear(0x3033)` 的地方；启动路径（irom `0x42BF`、`0x586B`）也写这个寄存器，但那时时钟是关的。

- `gpce4.cpp: timebase_clear_w()` 记一次写并置 `m_time_set_seen`；
- `clock_sync()` 先消费这个标志：`take_time_set() && snapshot_clock_valid()` 就把客人的
  `hh:mm:ss` 收为新锚点（`wallclock_adopt_local()`），不再纠偏；
- `0x0CB0 == 0` 的那些写（启动初始化）不采纳。

同时修掉两颗地雷：

1. **种子不再每帧硬写。** v1.11.1 早期版本为了"赶在 CONTINUE 提示之前设好时间"，每帧都写
   `0x0CB0=1`；而 ROM 的时间设置界面**每帧把它清 0**，两边对打的结果是画面停在开机 logo、
   客人停在 ROM 等待循环（实测 `scr=001C` 但 fb 还是 logo）。改成最多试 4 次就收手：
   成功则 `clock running`，失败则 `clock seed gave up ... waiting for the player`，
   把时间交给玩家 + 采纳路径。
2. **一个一次性种子会被 ROM 的启动清零覆盖。** 种子从"第 120 帧一次"改为"第 300 ms 起每帧写、
   直到活下来"，正常开机会在 1.3 s 内打出 `clock running 01:26:09 (nvs)`，早于玩家能按到
   CONTINUE。

## 3. 验证

新增两个测试钩子（都是控制台，发布版保留，和 `D`/`U`/`i` 同级）：

- `y <hh> <mm> <ss>`：一次性重放 ROM 的提交序列（RTC 三字 + `0x0CB0/0x0CB1/0x0CB2` +
  `0x3054=1` + `0x3033=0x5555`）。必须一次性完成——分条发命令时，`clock_sync` 会在两条
  命令之间把中间值纠回去，这本身就是"为什么必须原子提交"的证明。
- `j <addr> <val>`：写任意地址（`Q` 只能写 RAM），用来单独验证 `0x3033` 标志。

实测：

```
y 9 41 30
ACK y 09:41:30
CLK guest=09:41:30 wall=09:41:31 dev=1 steps=2 holds=21 snapf=0 seed=1 tbw=2 src=guest en=1

# 31 秒后仍然是我设的时间，并且在自己走
CLK guest=09:42:01 wall=09:42:01 dev=0 steps=10 holds=131 src=guest en=1

# 再用 t 恢复真实时间
ACK t 01:35:21 src=console tz=+480 guest=01:35:21 / offset 0 s
CLK guest=01:35:21 wall=01:35:21 dev=0 steps=11 src=console en=1
```

`src=guest` 出现即证明采纳生效：锚点被改成玩家设的 09:41，而不是被纠回 01:27。

## 4. 仍然要玩家按的那一步

关机重开后 ROM 自己的流程是：标题 → A+C → CONTINUE/RESET → CONTINUE → 时间设置界面 → C。
固件会在 300 ms–1.3 s 内把 RTC 设好，所以时间界面打开时暂存值（`0x085C/0x085D`，由
`0x203DCE` 从 RTC 装入）已经是当前时间；直接按 C 确认即可，调整过的时间也会被采纳。
这一步是 ROM 的设计（真机没有 RTC，断电后必须确认一次时间），不是固件能在不碰 ROM 的前提下
绕过的。
