## 3. 核心阻碍：设备上的 ROM 不读按键

### 3.1 决定性证据

在 `Gpce4::ioa_data_r()` 和 `ioa_buffer_r()` 加计数器后实测：

| 探针 | 设备（3.5 s） | host emu（12 s） |
|---|---|---|
| `ioa_data_r()` 调用次数 | **0** | 1498 |
| `Z 0850`（64 Hz 帧节拍） | `0000`（恒） | 递增 |
| `Z 3054`（INT2_Status） | `0000`（恒） | 有值 |
| `Z 3053`（INT2_Ctrl） | `0205` | `0205` |
| `pc` | `200343`（恒定） | `200343` → 之后进时钟界面 |

**ROM 从来没有执行到读 PORTA 的代码，所以按键当然无效。**
用户听到的"按键有声音"来自 host 层 `update_buttons()` 里的 `audio_beep()`，与 guest 无关——这条能对上他的原话"按键有声音但进不去游戏"。

### 3.2 已知的循环地址

| 地址 | 含义 | 出处 |
|---|---|---|
| `0x200343` | PRNG/延时循环 `0x2002F4`–`0x200324` 的收尾（`9898` = `pop bp,sr,pc`） | 子 agent 分析 |
| `0x230321` | flash 里的帧节拍等待循环：`call PRNG` → `r4 = ds:[0x0850]` → `cmp r4,0` → `je`（-8）→ `[0x0850] -= 1` → 回帧体 | `digimon-passport` 侧分析 |
| `0x000321` | 同一段循环的 RAM 副本（游戏把 block 搬到 RAM 后跑） | `unsp_glue.cpp:615` |
| `0x486B` | IRQ7 ISR 入口（向量 `0x401F`），`0x4888` 做 `[0x0850]++`，`0x4890` 清 INT2 bit0/bit2，`0x4897` `9A98 reti` | 子 agent 分析 |
| `0x200300` | `kGuestResumePc`——熄屏 park 目标（卡带区空闲循环） | `app_main.cpp:101` |

### 3.3 `tick()` 内部探针（20:22 那版固件）

```
[tick] now=160012832 any=1 stat=a0000000 p64=1500000 n64=160500000 en=1
[tick] now=200016261 any=1 stat=a0000200 p64=1500000 n64=201000000 en=1
[tick] now=240019354 any=1 stat=a0000000 p64=1500000 n64=241500000 en=1
```

解读：64 Hz 源的 `period=1500000`、`next` 正常推进、`source_enabled(3)=1`，但 `m_interrupt_status` 里**只有 bit31 + bit29，从来没有 bit2**。
`SRC_TIMER_64HZ = 2`（`gpce4.cpp:44`），`irqs[3] = SRC_TIMER_64HZ`，所以 `m_interrupt_status |= (1u << 2)` 应当出现。**位图对不上，说明中间还有一层把 64 Hz 置位吞掉或清掉。**

### 3.4 IRQ7 门控公式（两版 gpce4.cpp 一致）

```cpp
bool irq7;
if (irq7_mame_quirk) irq7 = (s & (1u<<2)) && (c2 & 0x0004);
else irq7 = ((s & 1u) && (c2 & 0x0001)) || ((s & (1u<<2)) && (c2 & 0x0004));
set_line(UNSP_IRQ7_LINE, irq7);
```
`c2 = 0x0205` 没问题；`s` 里没有 bit2 —— 所以 `irq7` 恒 false，ISR 一次都不进，`[0x0850]` 永远是 0。

## 7. 上一任犯的错（别重复）

1. **用 `V` 命令的 `Compile time: Nov 22 2026 20:41:00` 判断固件新旧。**
   `grep 'Compile time' firmware/digicore-c3/main/*.cpp` 只命中 `app_main.cpp:422` 的一句注释，这串 banner 不随增量编译更新。**正确判据**：`firmware\digicore-c3\digicore-c3-full.bin` 的时间戳 + `build\esp-idf\main\CMakeFiles\__idf_main.dir\app_main.cpp.obj` 的时间戳。因为这条错误，我连续几轮以为"改了没生效"，浪费了大量时间。
2. **在"按键极性"上绕了两轮。** emu 的 `--press` 是直接 `set_port(0, value)`，与设备侧的 `update_buttons()` 语义不同，不能拿 emu 的极性结论直接推设备。应先看 `Z 3000` 的实际读数。
3. **反复假设 `[0x0850]` 是门控，试了 4 种注入方式。** 每次都失败但没有及时收敛到"`bit2` 从未置位"这个更上游的事实。教训：**先在寄存器层确认位图，再改行为**。
4. **AOT 支线花了很久**（host 绿屏、影子校验器、逐帧比对）。那是真 bug，但对设备无影响，属于走错分支。
5. **没及早怀疑设备独占的优化代码。** `firmware/.../unsp_glue.cpp` 有 1632 行，比 host 版多近 400 行（`hot_prng_n()` / `wait_loop_collapse()`），这些是性能优化，也是行为偏差的高风险区。**两份代码不同这件事应该在第一天就逐文件 diff。**
