# 第八轮审计：续航优先，清掉待机与快进里的重复工作

日期：2026-11-28  
基线：v1.18.0 → 本轮 **v1.19.0**  
题目：在不影响现有功能与体验的前提下提高电池续航；继续找性能提升；清理无用冗余。  
性质：第三方审计视角的团队作业（五路并行取证 + 两路交叉互审 + 主审裁决、改码、编译、真机验证）。

---

## 0. 结论先说（三句话）

1. **续航的瓶颈不在屏幕，而在 CPU。** 待机 19 s 后背光已经灭、画面已经不再推（`blit_pct=0`），
   但 guest 仍以 56 fps 全速跑，`guest_pct` 51–56 %；游戏时间必须继续走，所以「停 guest」不是选项。
   本轮能安全切的，只有「每帧重复做、结果不变」的那部分。
2. **最大的一笔在快进提示条**：`LAPSE 60X C=STOP` 是静态卡，却每帧重推 10,560 B 阻塞 SPI
   （约 2.1 ms，12 % 帧预算）。改成按文本变化推一次后，快进时 `rows=0`、`blit_pct=0`，
   这笔开销整笔消失。第二笔是帧末忙等 1.5→1.0 ms（约 3 % 墙钟）。
3. **本轮交付**：镜像 −224 B、字体副本 −295 B、快进每帧 −2.1 ms、待机每帧 −0.5 ms 忙等、
   PRNG 折叠路径去掉每 pass 19 次 DRAM 访问（宿主逐位等价）；功能验收通过。
   按电流账估算，**待机续航 +3 % 左右、快进场景 +3–4 %**——是几个百分点，不是数量级；
   数量级要靠降频/深度待机，而它们都会改游戏时间或唤醒体验，本轮明确不动（见 §7）。

## 3. 续航账：钱花在哪，能切哪一笔

### 3.1 三种场景的电流构成（按数据手册量级估算，非实测）

| 场景 | 背光 | CPU 平均 | 面板/功放/其他 | 合计（估） |
|---|---|---|---|---|
| 亮屏游戏 | 80 % ≈ 24 mA | ≈ 14 mA（55 % × 20 + 45 % × 7） | ≈ 7 mA | **≈ 45 mA** |
| 待机（背光灭） | 0 | ≈ 14 mA | ≈ 6 mA（面板扫描 2、功放 3、LDO 1） | **≈ 20 mA** |
| 快进（睡眠黑屏） | 0 | ≈ 14 mA + toast SPI | ≈ 6 mA | **≈ 20–22 mA** |

结论：**背光是亮屏时最大单项（约一半），CPU 是待机时最大单项。**
背光默认 80 % 是用户可感知的亮度，不改默认；待机 CPU 承载的是游戏时间，不能停。
所以本轮只切「重复劳动」，不改「必须做的功」。

### 3.2 本轮切掉的重复劳动

| 项 | 原来每帧付多少 | 现在 | 依据 |
|---|---|---|---|
| 快进提示条 | 10,560 B 阻塞 SPI ≈ 2.1 ms + 0.5 ms 渲染 | 只在文本变化时推一次 | `R8_app_persist.md` AP-03；真机 `rows=0` |
| 帧末忙等 | 1.5–2.5 ms 自旋 | 1.0–1.99 ms | `R8_power.md` F4；互审修正为 0.5 ms/帧 |
| `hot_prng_n` | 每 pass 11 读 + 8 写 guest RAM | 循环内局部，尾写 6 字 | `R8_core.md` R8-C1；宿主 200×8 用例逐位一致 |
| fps 叠加层 | 待机每秒 576 B | 待机/菜单不推 | `R8_display.md` DISP-02 |
| 字体副本 | 两份 295 B `.rodata` | 一份 | `R8_app_persist.md` AP-01；镜像 −224 B |

### 3.3 为什么不做降频 / 深度待机

- **DFS 降频不成立**：待机仍有约 14 ms/帧的 guest 工作（占空比 84–90 %），没有可切的 idle 窗口；
  `esp_pm` 只会在 WFI 里降频，而 WFI 只剩几毫秒。
- **强制 80 MHz 会改游戏时间**：模拟器吞吐约 1.8× 实时，80 MHz 下只剩 0.9×，
  同样 guest 周期要 2 倍墙钟，宠物成长慢一倍；要补回来就得每帧跑 2 倍周期，重绘场景超帧预算。
- **light sleep 会停游戏时间**：待机 1 秒醒一次批量补周期在原理上可行，但要保存/恢复 SPI、I2C、
  USB Serial/JTAG，唤醒还要重初始化面板；收益可能 30 %，风险是「唤醒黑屏/丢按键」，留作下一轮专项。

## 5. 裁决：哪些团队结论被降级，为什么

| ID | 原结论 | 裁决 | 理由（互审原文摘要） |
|---|---|---|---|
| R8-C1 | `hot_prng_n` 每 pass 19 次 DRAM，P0 | **accept，已落地** | 反汇编复核属实；hoist 逐 pass 等价，唯一风险是 `[sp]` 与 0x0600 别名，实测不重叠 |
| F4 | spin 1.5→1.0 ms，P1 | **accept，已落地** | 与 R7「不动 spin」不冲突：只改覆盖窗，不删机制；收益修正为 0.5 ms/帧 |
| F3 | crcwatch 每 5 s 日志，P0 | accept（未落地） | 属实，但收益只有 0.08 %，且看门狗负责冻结恢复，暂不碰 |
| F6 | ST7789 无 SLPIN，P1 | accept（未落地） | 属实，省 1–2 mA，但唤醒 +150 ms，需产品决定 |
| F2 | fps 叠加层「盖住 STANDBY 卡」，P0 | **downgrade，已落地门控** | 叠加层在 (2,2)，窗口在 (64,24)，盖不到卡；能量≈0；门控仍保留（无副作用） |
| F1 | 待机停 guest 可省 20 mA，P1 | **downgrade** | 停 guest 会停成长/进化；`clock_sync` 仍会把表盘拉回墙钟；风险栏不完整 |
| F5 | 仅待机开 DFS 省 8 mA，P1 | **downgrade** | 待机没有可切的 idle 窗口；要么强制 80 MHz 改游戏时间，要么先降 guest 工作 |
| F9 | 待机只擦 3 扇区、活跃 7 扇区 | **downgrade** | 两份报告互相矛盾；实测 `snapshot pc=005376 frame skipped`，待机 PC 在 ROM，非 resumable，fbsave 不写 |
| R8-C2 | AOT 重叠块入口桩省 243 KB，P1 | **downgrade P2** | 与 R7 D4 逐字重复；1,048/1,097 重叠块 census 零命中，从不执行就不会 miss，「降占空比」不成立 |
| R8-C6 | 待机帧提前进 WFI，P1 | **downgrade** | 与 C1 合并；LFSR 必须确定性推进，不能跳 |
| DISP-01 | SPI 实际 40 MHz、常量写 80，P0 | **reject（主审采纳互审）** | IDF 对 80 MHz 请求走 `clk_equ_sysclk`，全链路无钳位；若线上真是 80，改常量会让整窗 7.37→14.75 ms；只该改 `display.c` 注释，不动常量 |
| AP-03 | toast 每帧重推，P1 | **downgrade，但已落地并补缺口** | 现象成立；push-once 版本最初没有失效钩子，菜单卡推满 240 行会让提示条永久消失。已补：菜单打开时置 `s_toast_invalidate`，关闭后重推；电池角故意不作为失效源（它与提示条右缘重叠，互相重推会闪烁） |

互审还补了 5 条遗漏，其中两条进入下一轮：
- **M1**：`hot_prng_n` 的 16 位掩码脚手架——236 条/pass 里约 130 条是 `slli/srli/and/seqz`，
  32 位化保守可省 70 条/pass，收益约 C1 的两倍。
- **M5**：`wait_loop_collapse` 每次调用 memcpy 32 B `HotState` + 回写 8 寄存器，19,154 次/s ≈0.5 %。

## 6. 验证

### 6.1 编译与体积

| 项 | v1.18.0 | v1.19.0 |
|---|---|---|
| app 镜像 | 1,134,032 B | **1,133,808 B** |
| sha256（app） | — | `B594C43C10A725C878A40B7586D05F6A016EF4085A16BD5B37386E394D2381F2` |
| DRAM 静态余量 | 87,176 B | 87,176 B |
| `execute_run` / `wait_loop_collapse` | 20,802 / 2,104 B | 20,802 / 2,104 B |

### 6.2 宿主等价测试

`tmp/prng_equiv.py`：把新旧 `hot_prng_n` 逐行转写，200 组随机种子 ×
n ∈ {0,1,2,3,7,64,999,5000}，比较 0x0600..0x0607、`sb`、`r1..r4`。
结果：**all cases identical**。这是改动 3 的直接背书；旧的逐 pass 写回与新的一次性写回在
折叠路径上不可区分（折叠期间中断延后，返回后才 `check_irqs()`）。

### 6.3 真机验收（COM4，v1.19.0）

- 启动：`VER ver=1.19.0`；`BOOT_OK`；快照从 record 2 恢复（`seq=5092`）。
- 待机：16 s 进 STANDBY 卡，19 s 背光灭；`guest_pct` 51–56，`ft` p50/p95 = 16/32 ms。
- 快进：`f 2` → `lapse notice up (60X)`；60 s 内 `LAPSE 60x` 每 5 s 一行、时钟连续；
  `rows=0`、`blit_pct=0` 证明提示条不再每帧重推；`C` 键仍能停止快进并把时钟收锚。
- 按键/菜单/存档：长按 A、A/B/C 导航、快照 `snapshot pc=005376` 均与基线一致。
- 冻结看门狗：本次运行未出现 `framebuffer frozen`（快进场景 scr=001C），未触发误踢。

### 6.4 帧时（诚实记录）

`J 1` 采样窗口内：稳定态 `ft` p50 16 ms、p95 32 ms、`gmax` 9.5–10.5 ms；
快进时 `guest_fps` 56.2–56.6，与 v1.18.0 同场景一致。
**本轮没有把「省下的 2.1 ms」兑现成更高的 fps**：帧预算自适应会把节拍拉回 60 Hz，
省下的是 SPI 占空比与忙等，体现在电流而不是帧率。这一点不写成「提速 12 %」。

## 7. 不动的清单（防误删）

| 项 | 为什么留 |
|---|---|
| 降频 / DFS / light sleep | 会改游戏时间或唤醒体验；需专项 A/B，见 §3.3 |
| ST7789 SLPIN | 省 1–2 mA，但唤醒 +150 ms；产品决定 |
| 背光默认 80 % | 亮屏最大单项，但降亮度是用户可感知的体验变化 |
| AOT 入口桩 / 入口表裁剪 | 与 R7 D4 重复；1,048/1,097 重叠块 census 零命中；省的是 flash，不是周期 |
| `wait_loop_collapse` / `spin_collapse` | 冻结恢复与游戏时间的依靠；只做调用点预筛，不删机制 |
| fbsave 擦写（32 KiB） | 待机 PC 在 ROM（`pc=005376`），非 resumable，实际不写；活跃时 1 次/分钟 |
| 控制台命令表、NVS/save 分区、internal ROM | 验收/存档/启动的依靠 |
| 砖墙逐字节拷贝约定 | 与姊妹项目一致；1bpp 省 14 KB 但破坏约定 |

## 8. 下一轮建议（按性价比排序）

| 优先级 | 事项 | 预期 | 代价/风险 |
