**判据（必须同时满足）**：

| 项 | 值 | 说明 |
|---|---|---|
| `ES8311 id=83 at 0x18` | — | codec 在 I2C 上应答 |
| `first i2s write: err=0 sent=1024 of 1024` | — | I2S DMA 通路 |
| `ACK W pages=2 writes=4 crc=D5E4162B` | — | 存档路径自测 |
| `FB_CRC` | **`62C4882E`（冷启动）/ `38699DC5`（有快照）** | 两个值都对，取决于启动时有没有恢复 gueststate。**不是回归** |

**`FB_CRC` 的两个值别搞混**：`62C4882E` 是冷启动后的启动 logo（`fb[]` 有画面）；
`38699DC5` 是 `fb[]` 全 0（从快照恢复，或 ROM 熄屏后清屏）。两者都稳定可复现。

**采样陷阱**：打开 COM4 这个动作本身就会让 C3 复位。`tmp/send_cmd.py` 默认等 2.5 秒才发命令，
别改小 —— 0.3 秒会读到启动中途的半成品画面，曾经害我误判"判据变了"。

## 5. 待办（按价值排序）

### 5.1 比例字渲染器（`menu.cpp`）

现在是 `draw_char` 逐列画 5 px、`text_width = len * 6`。改成比例字：

- 给 59 个字符各配一个 `adv`（4/5/6/7），加进 `font5x7.inc`
- `text_width()` 改成 `for (c : s) w += adv[c]`
- `draw_char()` 用 `adv` 推进而不是固定 6
- 参考数字：Montserrat 14 大写墨高 10 px（我们放大 2× 后正好 14，偏高 4 px，可接受）；
  空格 3.75、`S` 8.69、`W` 15.75（单位 px，我们放大 2× 后要除以 2 取整）

**这一项对"看起来一样"的贡献最大。**

### 5.2 alpha 混合（`menu.cpp` 的 `card_line()`）

现在直接赋 RGB565。要混合得先取背景（`backdrop_px()` 已经实现，卡片外就在用它）：

- 卡片底：`out = (bg * 10 + fill * 90) / 100`
- 阴影：`out = (bg * 60 + 0 * 40) / 100`，宽 12 px，只画在卡片右下外沿
- **性能要测**：全屏 320×240 = 76,800 像素，160 MHz C3 上每像素两次乘法，
  得看能不能塞进一帧（68 ms 预算）。菜单是静态的，只在 `s_dirty` 时推一次，应该没问题。

### 5.3 A+C 的界面门（D2）

参考板判 `dg_ram(0x009)==1 && dg_ram(0x00A)==0`。我们没有读 guest RAM 的接口：

1. 给 `Gpce4` 加 `uint16_t ram_at(uint32_t addr) const { return ram[addr & 0x0fff]; }`
2. 加控制台命令（用空闲字母 `E`）：`E <addr>` 读一个 RAM 字
3. 在时钟页和游戏页各按一次 `E 9` / `E 10`，看值能不能区分
4. 确认之后再给长按 A 加条件

**地址没验证出来之前不要填** —— 填错会让 A+C 彻底不可用，比现在"任何界面都发"更糟。

### 5.4 观感：guest 清屏但背光还亮

ROM 熄屏时会清 `fb[]`，而模拟器的背光逻辑是独立的 16 s 定时器。结果：实机会黑屏，
模拟器还亮着显示黑屏。可选做法是监听 `fb` 是否全 0 来提前灭背光，或者干脆接受（现在是
AUTO OFF 设成 NEVER 时才明显）。

### 5.5 没做的杂项

- D8：菜单打开时 guest 是否该继续跑（参考板继续跑，我们冻结）
- D9：熄屏唤醒键的两个边沿都吞掉
- D10：最短保持 shim（50 ms）
- D14：`H 0` 的语义（注释说 off，实际一按下就触发）
- 屏幕版本号的开机 splash 形态（B 线收工时暂缓，现在菜单里已经能看到版本号）
