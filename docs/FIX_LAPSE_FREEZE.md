# 睡眠状态下时间快进导致画面冻结：定位与修复

日期：2026-11-28
基线：`digimon-color-passport` v1.17.1（`firmware/digicore-c3/main/`）
设备：FoloToy AI Passport（ESP32-C3，COM4）

---

## 1. 用户现象

- 数码兽**睡眠**状态下开启 `TIME LAPSE`，约 40 秒后画面冻结：睡觉动画（Z 字循环放大缩小）停止。
- 退出快进后恢复。
- 活动状态下似乎不出现。

## 2. 实测定位（设备真机）

| 场景 | PC | `0x0C88` | 帧缓冲 CRC | `blitpx` |
|---|---|---|---|---|
| 睡眠 + 快进，正常时 | `0x207CA3`（帧体） | `0004` | 持续变化 | 持续增长 |
| 冻结时 | `0x5251`/`0x5376` | `001D` | 固定 `C49B9242` | 定格 |

- 冻结时 **guest 时钟仍在推进**（关掉快进也在走，1 s/1 s），说明 CPU 没有死：帧体在跑，只是不再绘制。
- `0x0C9C = FFFF`、`0x0C9D = 2600`、`0x081F = 0`：`0x0C9C` 是 ROM 自己的初始化哨兵，不是原因（人为写入后 ROM 会在下一帧改回 4，且不会冻结）。
- 人为写 `0x0C88 = 4` 能把状态拉回宠物画面，但**画面仍不重绘**。

## 3. 根因

帧体在 irom `0x5357` 用 `[0x0CB2]`（"秒已进位"）置 `[0x0851]` 的 **bit 1**，在 `0x539F` 用按键边沿置 **bit 0**。`0x53AC` 检查 bit 1、`0x53BD` 检查整个字：

```
53A8: r4 = [0851]
53AC: r4 &= 2
53AD: cmp r4, 0
53AE: je  53B0          ; 没有秒进位
53B0: jmpf 5217         ; → "本帧无事可做" 路径
```

`0x5217` 之后顺序执行到 `0x52F5`，即写 `0x3050/0x3051/0x3035/0x3036` 的关机序列。host 侧在写 `0x3036` 时把 PC 拽到 `0x200300`（`gpce4.cpp` `system_sleep_w()`），状态机从此不再回到绘制分支——**面板保留最后一帧，动画停住**。

关键点：**这一事件标志只有帧体自己能产生**。一旦 guest 走进 `0x5217` 的等待路径，`0x5BE2` 不再被调用，`0x0CB2` 不再置位，`[0x0851]` 永远是 0 —— **死锁**。

睡眠状态更容易踩中，是因为睡眠时没有按键（bit 0 不来），而快进把 RTC 进位的节奏改变，让"本帧既无按键也无进位"的窗口变长。

实测：在冻结现场把 `[0x0851]` 置 3（bit0|bit1），`blitpx` 从 188472 立刻涨到 238777、CRC 改变、PC 回到 `0x200343` —— **确认这是唯一的锁**。

## 4. 修复

两处改动，都在 `main/app_main.cpp`：

### 4.1 快进改为"连续走时"

原实现用 ROM 的 `0x0D03` 标志（一次进位 +60 s），配合微秒周期注入。改为**每帧注入一次普通进位（+1 s）**，倍率等于帧率（设备实测 52×），时间连续，不再有 60 秒跳变。

- `sync_time_lapse()`：`0x0D03` 恒为 0。
- `time_lapse_step()`：帧计数驱动，15X = 每 4 帧一次，60X/300X = 每帧一次。

### 4.2 帧缓冲停滞看门狗

每 30 帧对 `s_soc.lcd.fb` 算一次 CRC。当 `0x0C88 ∈ {4, 0x1D}` 且连续两次 CRC 相同（约 1 s），判定停绘并执行：

```cpp
s_soc.ram[0x0851] |= 3;          // 补上"按键 + 进位"事件，踢回绘制路径
if (hscr != 0x0004u)
    s_soc.ram[0x0C88] = 0x0004u; // 把被切走的状态拉回宠物画面
```

日志：`framebuffer frozen on scr=001D; kicking [0x0851] (n)`。

## 5. 验证（COM4 真机）

| 版本 | 结果 |
|---|---|
| v1.17.1 原始 | 睡眠 + 60X 约 8 s 后永久冻结，只能复位 |
| 平滑快进（未加看门狗） | 时间连续 52×，但跨日仍冻结 |
| 平滑快进 + 看门狗（1.5 s 阈值） | 45 s 内 3~4 次冻结，每次 1.5 s 内恢复，`scr` 保持 4、`blitpx` 单调增长 |
| 平滑快进 + 看门狗（1.0 s 阈值） | 40 s 内 3 次，每次 1 s 内恢复 |

## 6. 未解决

- **冻结仍会周期性发生**：60X 下约每 12 s 一次（对应 1x 下约 12 分钟一次），每次约 1 s 画面不动。原因是 ROM 会主动切到 `0x1D`（某个切换后不绘制的界面），而本移植没有实现该界面的绘制；看门狗只是把状态拉回来。
- 真正的零卡顿需要让 `0x1D` 的绘制路径工作，或找到触发切换的计数器并在 host 侧抑制。两者都还需要一轮 PC trace。
- `system_sleep_w()` 里的自赋值死分支（R7-11）仍然存在，本次未动。

## 7. 复现步骤（设备）

```
y 0 30 0        # 或任意时间跳变
f 2             # 60X；宠物需处于睡眠状态（游戏内夜间）
# 8~12 s 内出现 framebuffer frozen 日志
```
