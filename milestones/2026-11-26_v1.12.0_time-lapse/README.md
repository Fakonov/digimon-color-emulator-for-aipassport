# v1.12.0 — 时间倍速（TIME LAPSE）

日期：2026-11-26
镜像：`digicore-c3-v1.12.0.bin`，1,021,840 B，SHA256 `5767F157…0E9076B`

## 这一版做了什么

ROM 自带一个 60× 进位开关（RAM `0x0D03`，internal ROM `0x5C10` 处 `秒 += 0x3C`）。它改的是**时间流速**而不是时钟数值：`[0x0CB2]` 分钟脉冲照常产生，`0x209349` 钩子照常把 `0x0CE6..0x0CE9` 倒计时各减 1，所以成长、饥饿、睡觉、死亡都跟着同一节奏加速，规则与顺序不变。手册那句"改时间不会加速成长"反证了成长挂在脉冲上，不挂在 `0x0CAF/CAE/CAD` 的数值上。

菜单新增 `TIME LAPSE` 行（OFF / 15X / 60X / 300X，NVS 键 `lapse`）。三档都由宿主注入进位，不依赖 ROM 自己的 2 Hz 中断——这个卡带长期 `int off`，只开 `0x0D03` 不注入时实测只有 5.9×。

## 实测（COM4，设备内 `LAPSE` 行采样）

| 档 | 实测倍率 | 实际 10 分钟 → 游戏时间 |
|---|---|---|
| 15X | 11.9× | 约 119 分钟 |
| 60X | 53.7× | 约 537 分钟 |
| 300X | 300× | 约 3000 分钟 |

15X/60X 偏低 10–20%：测量时设备无存档、游戏在标题与主界面之间切换，个别帧不跑帧体，注入的进位被下一帧清掉。有宠物在育成画面时帧体每帧都跑，应更接近标称（未验证）。

## 提示与取消

- 提示条：窗口下缘单行 240×22（`y=216`，游戏窗口到 215 为止），内容 `LAPSE 300X  B=STOP`。
- 弹出时机：设置卡里切完档按 C 关卡；或控制台 `f 0..3` 直接开启。
- 模态：条激活期间只认 B（物理键或 `K` 注入），A/C 全吞，长 A 开不出菜单。
- 按 B：停倍速、关条、把虚拟时间收成新锚点。

## 宿主配合

- `clock_sync()` 快进时只跟随不纠偏（`wallclock_track_local()`），否则每 250 ms 会把时钟拽回去并清掉 `[0x0CB1]`。
- 关档、快照前 `wallclock_adopt_local()`；恢复后 `sync_time_lapse(true)` 压掉记录里的旧标志。
- 非注入帧把 `[0x0CB1]` 清零，否则 ROM 自己的半秒 tick 会多送一次进位（实测同一档在 5.9×–51× 之间乱跳）。

## 已知限制

- 倍率随游戏状态小幅浮动（帧体执行率），不是硬实时。
- 快进把死亡条件一起加速：手册的"连续受伤 6 小时 / 饥饿 12 小时"按 300× 就是 1.2 分钟 / 2.4 分钟。
- 断电/读档一致性未测；提示条像素需人眼确认（串口只证明推送成功）。
